## 3. What do you think is the most interesting trend in test automation today?
One of the most popular trend is using AI to help builing up automation capabilities.
In the past, resources like Stack Overflow and other forum are were the main places to search for solutions and troubleshooting the diffcult scenarios. Nowdays AI tools can help to analyse and resolve lots of common issues much faster. For example finding the element locators, improving wait strategies, debugging erros.

## 4. How would you implement test automation in a legacy application? Have you ever
done this before?
While working at DXC, I developed an automation solution for MSD account and its legacy system. It was built based on Karate framework and automated both UI and API testing. 
For a legacy application, I would first understand the key business flows and any limitations of the existing system, such as supported functionality, available APIs, environments, or technical constraints. Then I would identify which areas are feasible and should be prioritised in automation solution.
Legacy system might not always be a bad news for automation. In some cases, older applications have relatively static page components, which can make element identification easier than in some modern applications where elements are generated dynamically.
